SPRITE SOUND FRAMEWORK - REVERBERATED
ORIGINAL 1.1 TO CURRENT 1.4.2 SOURCE COMPARISON
Updated: November 1, 2026

SCOPE AND EVIDENCE
This replaces the older method comparison in a separate copy. The supplied document and game/project files were not edited.
Baseline: seven preserved source files extracted from the original 1.1 archive. All seven SHA-256 hashes match the recorded original ZIP source hashes in EARLY-HISTORY-EVIDENCE.json. The original archive path is no longer available; this review uses those verified extracted files.
Target: the ten C# files beside the supplied ORIGINAL-METHOD-COMPARISON.txt in the SSF-Reverberated-1.4.2 project folder, read on the date above. Its manifest says 1.4.2. This is a source comparison, not proof that any installed .dfmod contains these exact files.
See COMPARISON-EVIDENCE.json for exact paths, hashes and per-file change counts.

HOW TO READ THE RESULTS
UNCHANGED: identical C# tokens, ignoring comments and whitespace.
LOG ROUTING: identical tokens after replacing SpriteSoundLog.Info/Warning/Error calls with Debug.Log/LogWarning/LogError. Routing can change where and when messages appear; it does not mean the logging behavior is identical.
CHANGED: other C# tokens differ. This classification alone does not establish a runtime bug or improvement.
ADDED / REMOVED: a method signature exists on only one side. A changed signature appears as a removal plus an addition, even when it replaces the same job.
Line numbers point to declarations in the exact source snapshots recorded here. Parameter modifiers such as out are included.
The inventory includes every MethodDeclarationSyntax node in both sets, including methods in entirely new files. Constructors, fields, properties, attributes, imports, nested types, comments and formatting are covered by the full source diff, not classified as methods.
SOURCE-CHANGES-1.1-to-1.4.2.diff records every line addition/removal in all ten C# files, including comments. It is intentionally more detailed than the plain-language explanation.
DOCUMENT-UPDATE.diff records every edit from the supplied comparison document to this updated copy.

WHAT CHANGED AND WHY

SpriteSound_DFUIntegration.cs
Init now establishes the optional logger/settings and starts a persistent Harmony bootstrap. It leaves the mod unready until startup checks finish and avoids duplicate startup. The original initialized its patches and discovery directly.
ApplySettings is new and applies the logging checkbox without restarting playback. SpriteSoundHook.OnDestroy adds logger cleanup.
Attach leaves an existing same-key emitter alone so repeated discovery cannot restart it, while a changed key still triggers initialization.
The scanner's event handlers, scan routines, manager creation and scan timing methods remain token-identical to 1.1. Discovery itself is inherited, not a new feature.

SpriteSound_NPCFRPatch.cs
This file is no longer LOG ROUTING ONLY. The loose-DLL loader and reflected Harmony overload selection were replaced in 1.4.2.
Init() is replaced by Init(Mod). It verifies the dependency's HarmonyRef derives from the same Harmony type, requires exactly one loaded 0Harmony assembly with version 2.4.2.0, and installs the required vanilla cleanup patch before considering optional NPC Flat Replacer support.
GetHarmonyPatchMethod() is removed. PatchTarget(MethodInfo,Assembly,MethodInfo,MethodInfo) is replaced by PatchTarget(MethodInfo,string), which calls Harmony directly and records installed targets.
VerifyInstalled checks that every recorded target still has an SSF-owned postfix declared by this patch class. It does not compare each postfix method name and is not continuous monitoring after startup.
Shutdown removes patches for SSF's owner ID only and clears its tracking state. It does not globally remove other mods' patches.
NoInlining attributes on the Harmony entry methods help keep library binding out of early dependency checks. A typed Harmony instance and installed-target list replace reflective state.
FindType and both identity postfixes remain token-identical to 1.1. Replacement prefixes are still saved as sound identities, and vanilla material assignment still schedules removal of stale identities.

SpriteSoundHarmonyBootstrap.cs - entirely new
Configure records the owning mod and startup instance. IsRunning exposes whether a bootstrap instance exists.
TryGetDependency checks the exact dependency filename, enabled state, load order and provider version of at least 2.4.2.2. The actual Harmony library version is checked separately in the patch helper.
Start requires one active provider component, waits one frame for its Start cleanup opportunity, installs patches, then waits another frame and checks that they remain installed. Only then does it attach discovery and mark SSF ready.
This ordering follows the reviewed provider's synchronous Start cleanup. It is not a general guarantee for future providers with different startup behavior.
Fail leaves SSF unready, logs the reason and requests owner-scoped patch cleanup. OnDestroy cleans up the owned session, readiness state, singleton reference and logger.

SpriteSoundConfig.cs
GetConfig changes only message routing; BuildJsonPath is unchanged. New musicianSyncGroup and musicianGroupRadius fields allow local grouping, with a default radius of 12 world units. These field additions are why the whole file is CHANGED even though its two methods have no other token changes.

SpriteSoundEmitter.cs
Awake creates an SSF-owned audio child and filter instead of sharing the billboard's AudioSource. Native components can no longer rewind the same source SSF is using.
Initialize and Reactivate preserve eligible existing playback, refresh configuration/range state and hand musician playback to the ensemble system. Enabling defers the refresh; disabling and destruction stop owned work and restore native audio state.
Playback generation numbers act as cancellation tickets. StopPlayback invalidates old work, and the guarded playlist helpers prevent an old load or coroutine cleanup from taking over a newer session.
The original PlaylistCoroutine(string) is replaced by PlaylistCoroutine(string,int), with validity checks around loading and playback. Established fixed loops can pause outside hearing range and continue from their stored position; pending or randomized playlist work is not promised that same treatment.
SuspendNativeAnimalAudio and RestoreNativeAnimalAudio selectively control native random playback for animal keys only when a replacement is ready, saving and restoring the previous enabled states.
SlowSensorUpdate and the range helpers use consistent effective distance, a boundary margin and smooth outer fades for logarithmic sounds. Volume follows DFU's sound-volume setting, and UpdateVoicePriority favors nearby sources.
HasStaticOccluder filters triggers, billboards and emitter colliders from obstruction checks; its name does not mean it checks Unity's static flag.
SetPaused separates game pause from range suspension and guards loop starts/resumes. Playlist loading waits for an appropriate unpaused start. Frame-triggered one-shot loading has generation/range/activity checks but does not have the same post-load pause wait.
ScheduleEnsemble and StopEnsemble expose scheduled playback to the conductor. Musician sources use fixed pitch and no Doppler; normal random selection and frame-triggered one-shots do not drive musician playback.
TraceAnimalPlayback and voice diagnostics report playback state, timing, distance and source ownership when logging is enabled.
Start and CheckFrameTriggers retain their original method tokens. Their callers and surrounding state changed, so token equality does not guarantee identical overall behavior.
The original 1.1 already assigned loaded clips before playback. A missing assignment was an intermediate regression that was repaired, not a defect being attributed to the original.

SpriteSoundEnsembles.cs - entirely new
Tick drives discovery and group updates. Discover builds local groups by scene, label and pairwise distance, replacing the original single global musician timeline.
TickBand chooses from songs shared by all members, manages loading, pauses, scheduled starts, range return, recovery and periodic diagnostic samples. Song changes are coordinated for the group.
Position calculates the shared song position and clamps elapsed time before a scheduled start. This lets pause/resume and late arrivals use the same timeline.
FinishLoad validates loaded parts and duration compatibility. Parts differing by over 100 milliseconds are rejected; the shortest acceptable part determines the group's end. Starts are normally scheduled 150 milliseconds ahead on Unity's audio clock.
RejectSong marks an unusable song; DisposeLoad releases pending load work; StopSources stops the group's sources; ClearSong resets song state. Retire and Reset discard groups and obsolete work during regrouping or world transitions. Log emits group diagnostics only when enabled.
New Band/Start state and collections store membership, shared choices, loading, scheduled timing and pause positions. Full declarations appear in the source diff.
This coordinates playback positions, not musical composition: matching filenames/durations do not fix different arrangements, tempo, leading silence or animation timing.

SpriteSoundLog.cs - entirely new
BeginSession sets the session's mod-relative location and logging state. SetEnabled toggles diagnostics without restarting emitters. Enabled exposes whether diagnostics are enabled.
Info, Warning and Error route messages through Write. Operational warnings/errors can still reach Unity with diagnostics disabled; ordinary diagnostic sampling is skipped when disabled.
EnsureOpen creates Mods/Logs/SSF and uses lowercase ssf.log and ssf-prev.log in the current source. It rotates on the first enabled logging activation of a game session and appends on later activations in that session.
Re-enabling writes a resumed-session header, not a new-session header. Leaving logging disabled for a whole session does not rotate previous logs.
Fail handles file-writing failure with Unity-log fallback. CloseWriter releases the writer; EndSession closes the session. Old files under the former Mods/SSF/Logs path are not automatically migrated.
Current-path observation: the manifest's description still says Mods/SSF/Logs, which disagrees with the executable logger path. This report records that mismatch without changing the manifest.

SpriteSoundManager.cs
Awake adds logging of audio-device settings. BuildIndices changes only log routing; indexing and caching are inherited behavior.
Update drives the local ensemble conductor alongside pause forwarding. OnDestroy and ResetMusicianTrack reset ensemble state and obsolete work.
PickRandomMusicianTrack and PickRandomFromIndex are removed. MusicianSongs exposes the available song suffixes for intersection by the conductor; PickRandomVariant no longer changes global musician state for ordinary random sounds.
Registration, clip caching, file lookup, attachment eligibility and path construction methods remain token-identical to 1.1. Global musician state is replaced by the ensemble system; new fields and removed declarations are recorded in the full diff.

SpriteSoundIdentity.cs and SpriteSoundKeyResolver.cs
Both files are token-identical to 1.1. Comments and formatting may differ. Identity storage and lookup order remain inherited behavior.

PACKAGE CONTEXT AND LIMITS
The current manifest declares the required daggerfall.harmony dependency and version 1.4.2; modsettings.json provides the logging checkbox. These are supporting configuration changes, not C# methods.
This review parses C# syntax and compares source tokens; it does not compile the mod, build platform bundles, inspect binary contents or run gameplay. Earlier gameplay results are separate evidence and are not rerun by this documentation update.
